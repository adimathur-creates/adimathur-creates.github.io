Compliance-ready by default: shipping AI-drafted advisor follow-ups safely

In asset management the hard part of GenAI isn't writing the draft. It's getting the draft approved, trusted and used. This is a plan, a test set and a working pre-check for one high-value use case: AI-drafted follow-up emails from wholesalers to financial advisors.

Built for: GenAI Product Manager, Franklin Templeton (India) Inside: problem · risk map · workflow · 18-draft test set with a live checker · metrics · rollout gates · audit record · use-case portfolio · SQL Jump to the checker

Independent work. Not affiliated with Franklin Templeton, and no internal information was used. Company facts come from public press releases and reporting. The funds, figures and emails below are fictional. The compliance checks are my proposed house rules based on my reading of FINRA Rule 2210's "fair and balanced" standard; I'm not a lawyer, and a compliance team would set the real rules.

The context

In Jan 2026 Franklin Templeton launched Intelligence Hub on Azure OpenAI for U.S. wealth distribution: meeting prep, list building, prioritisation. Expansion to more business lines and regions is planned.

The problem

The step after meeting prep is the follow-up email to the advisor. That's an external communication about funds. One wrong performance figure or a "will outperform" line is a regulatory problem, so every draft goes to manual review, and adoption stalls.

The answer

An automatic pre-check that blocks the dangerous drafts, sends doubtful ones to a reviewer, and clears clean ones. Measured against compliance reviewers' own labels before it's trusted.

2. The problem statement

Wholesalers want AI to draft follow-up emails to financial advisors right after meetings. Every draft is an external communication about funds, so it must be accurate, current, balanced and free of promises. Manual review of every draft doesn't scale, and an unchecked model will sometimes state a wrong or stale figure. Design the checks, the review flow and the evidence that let these drafts ship at scale, with zero serious violations reaching an advisor.

4. The workflow

1

Draft from approved sources only

The model drafts from the meeting notes plus the current approved fact sheet retrieved by fund and share class. It is instructed to quote figures only from that sheet and to include its "as of" date.

2

Automatic pre-check

Fast rule checks (figures, dates, periods, disclosures, phrases, products, personal data) run first, then an LLM judge looks for misleading claims the rules can't see. Result: clear, review or block.

3

Human review only where it adds value

Blocked drafts go back to the wholesaler with the reason shown. "Review" drafts go to compliance with the flags highlighted. "Clear" drafts can be sent, with a random sample still reviewed every week.

4

Log everything for audit

Every sent draft keeps its model version, prompt version, source fact sheet, check results and reviewer decision (section 8).

7. Rollout gates: from pilot to production

1

Offline gate

The test set grows from 18 to 300+ real, anonymised past drafts labelled by compliance. Pass: 100% recall on high severity, with false alarms low enough that reviewers don't start ignoring flags.

2

Shadow mode, 4 weeks

The pre-check runs on every draft but compliance still reviews everything. Measure agreement between checker and reviewer, case by case. Every disagreement becomes a new test case.

3

Pilot with 20 wholesalers

Auto-clear turns on only for drafts with no figures (thank-yous, scheduling, sending attachments), the lowest-risk group. Drafts with figures still get reviewed, but with flags highlighted.

4

Widen, one risk tier at a time

Auto-clear expands to drafts with figures only after shadow agreement proves out, with a weekly random audit forever. New regions start back at step 2 because their rules differ.

10. SQL I'd run weekly

1. Adoption: who uses it, and how much do they edit? 
SELECT region,
       DATE_TRUNC('week', created_at)                            AS week,
       COUNT(DISTINCT user_id)                                   AS active_wholesalers,
       COUNT(*)                                                  AS drafts,
       ROUND(100.0 * AVG(CASE WHEN sent_at IS NOT NULL THEN 1 ELSE 0 END), 1) AS sent_pct,
       ROUND(100.0 * AVG(CASE WHEN sent_at IS NOT NULL AND edit_ratio_before_send < 0.10 THEN 1 ELSE 0 END), 1) AS sent_light_edit_pct
FROM ai_drafts
WHERE use_case = 'advisor_follow_up'
GROUP BY region, DATE_TRUNC('week', created_at)
ORDER BY week, region;
2. Does the pre-check agree with compliance? (shadow mode) 
SELECT precheck_verdict,
       reviewer_verdict,
       COUNT(*) AS drafts
FROM ai_drafts
WHERE use_case = 'advisor_follow_up'
  AND reviewer_verdict IS NOT NULL
  AND created_at >= CURRENT_DATE - 28
GROUP BY precheck_verdict, reviewer_verdict
ORDER BY precheck_verdict, reviewer_verdict;
-- The cell that matters most: reviewer_verdict = 'BLOCK' and precheck_verdict = 'CLEAR'. It must be empty.
3. Is review getting faster? 
SELECT precheck_verdict,
       COUNT(*) AS reviewed,
       PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY EXTRACT(EPOCH FROM (reviewed_at - submitted_at)) / 60) AS p50_minutes,
       PERCENTILE_CONT(0.9) WITHIN GROUP (ORDER BY EXTRACT(EPOCH FROM (reviewed_at - submitted_at)) / 60) AS p90_minutes
FROM ai_drafts
WHERE reviewed_at IS NOT NULL
  AND created_at >= CURRENT_DATE - 28
GROUP BY precheck_verdict;
4. Which checks fire most, and which ones reviewers overrule? 
SELECT c.check_name,
       COUNT(*)                                                   AS times_flagged,
       ROUND(100.0 * AVG(CASE WHEN d.reviewer_verdict = 'CLEAR' THEN 1 ELSE 0 END), 1) AS overruled_pct
FROM draft_checks c
JOIN ai_drafts d ON d.draft_id = c.draft_id
WHERE c.result = 'FLAG'
  AND d.reviewer_verdict IS NOT NULL
  AND d.created_at >= CURRENT_DATE - 28
GROUP BY c.check_name
ORDER BY overruled_pct DESC;
-- A check overruled most of the time is costing reviewer trust. Fix or retire it.
5. Are we still using the latest fact sheet? 
SELECT d.fund_id,
       MAX(d.source_as_of)          AS newest_used,
       f.latest_as_of,
       SUM(CASE WHEN d.source_as_of < f.latest_as_of THEN 1 ELSE 0 END) AS drafts_on_stale_sheet
FROM ai_drafts d
JOIN fund_factsheets_latest f ON f.fund_id = d.fund_id
WHERE d.created_at >= CURRENT_DATE - 7
GROUP BY d.fund_id, f.latest_as_of
HAVING SUM(CASE WHEN d.source_as_of < f.latest_as_of THEN 1 ELSE 0 END) > 0;

11. What I'd ask in week one

  • How are wholesaler follow-ups reviewed today, and how long does a review take?
  • Which communications does compliance treat as pre-approval versus post-review, for each channel and region?
  • Where do approved fact sheets live, and how quickly does a new quarter's data reach the AI's sources?
  • What does "adoption" mean to the business sponsor: users, drafts sent, or meetings converted?
  • Which existing evaluation and Responsible AI templates does the team already use, so this fits rather than duplicates?

12. What this is not

  • No internal information. Fund names, figures and emails are fictional; the house rules are my proposal for compliance to replace.
  • 18 drafts can show the method, not prove the checker. The offline gate needs hundreds of real, reviewer-labelled drafts.
  • The rule checker is deliberately simple and visible. The LLM judge layer is described, not built here.
